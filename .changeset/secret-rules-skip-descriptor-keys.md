"@docker-doctor/cli": patch

`no-secrets-in-env` and `no-plaintext-secrets` no longer report a key that only describes a credential. A key is skipped when its last word says where the credential lives (`file`, `path`, `dir`, `sock`, `socket`), how long it lasts or how long it is (`ttl`, `timeout`, `seconds`, `length`), which one it is or which scheme guards it (`name`, `type`, `mode`, `driver`, `method`, `policy`, `provider`, `algorithm`), or whether it is on (`enabled`, `disabled`). That clears `SSH_AUTH_SOCK=/run/host-services/ssh-auth.sock`, `TOKEN_TTL_SECONDS=3600`, `AUTH_DRIVER=session`, `SECRET_NAME=my-app-secret`, `PASSWORD_POLICY=strict`, `PASSWORD_MIN_LENGTH=12` and `POSTGRES_HOST_AUTH_METHOD=trust`. The values `0` and `1` now count as on/off switches, which clears `MYSQL_RANDOM_ROOT_PASSWORD=1`. A key that ends in a word that can hold the credential itself, such as `AUTH_HEADER`, `PASSWORD_HASH`, `SECRET_KEY` or `API_TOKEN_ID`, is still reported. Because `no-secrets-in-env` reports an error, the score rises for files where these keys were the only finding. Rule messages also stop masking the value of such a key as `***`, since it is not a credential.
