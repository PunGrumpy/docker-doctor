## Default scan command

```bash
npx @docker-doctor/cli@latest [dir]
```

`[dir]` is the directory to scan and defaults to `.`.

| Flag | Alias | Description |
| --- | --- | --- |
| `--verbose` | `-v` | Show the affected file, line, an explanation, and a `Help:` fix hint for every diagnostic |
| `--score` | `-s` | Print only the numeric health score |
| `--json` | `-j` | Output the full report as JSON |
| `--config <path>` | `-c` | Use a custom config file; the path is relative to the current directory (or absolute) |
| `--version` | `-V` | Print the CLI version |
| `--help` | `-h` | Print usage for the command |

## Piped / CI output

`--score` and `--json` both suppress the interactive spinner and prompts, so they're safe to pipe or run in CI:

```bash
npx @docker-doctor/cli@latest . --score
```

```bash
npx @docker-doctor/cli@latest . --json > report.json
```

### Exit codes

The same rules apply to the default scan, `--score`, and `--json`:

| Code | Meaning |
| --- | --- |
| `0` | Scan complete, no `error`-severity diagnostics. Also returned when docker-doctor finds no Dockerfile or Compose file. The terminal output says so, and `--json` and `--score` print a warning on stderr. |
| `1` | Scan complete, at least one `error`-severity diagnostic. In interactive mode, also returned when docker-doctor can't write the workflow scaffold, the `.docker-doctor/` handoff files or the `.gitignore` entry for them. |
| `2` | Scan incomplete: one or more discovered files could not be read or parsed. The report and score cover only the files that were analyzed; the failures are listed on stderr. `2` wins over `1`. In `--json` output the affected files are listed under `failures` (report `schemaVersion` 4). |
| `130` / `143` | Interrupted (SIGINT / SIGTERM) |

### Environment variables

| Variable | Effect |
| --- | --- |
| `FORCE_COLOR=0` | Disable colors in the terminal report. `TERM=dumb` and a stdout that isn't a TTY also turn them off. |
| `CI`, `NO_ANIMATION`, `TERM=dumb` | Print the score box without animating it. This also happens when stdout isn't a TTY. |

The CLI doesn't read `NO_COLOR`. Set `FORCE_COLOR=0` instead.

## Install for agents

Install the Docker Doctor agent skill for your coding agents (interactive multi-select in a TTY):

```bash
npx @docker-doctor/cli@latest install
```

Non-interactive runs must name the agents:

```bash
npx @docker-doctor/cli@latest install --agent claude-code cursor
```

| Flag | Alias | Description |
| --- | --- | --- |
| `--agent <agents...>` | `-a` | Agent id(s) to install for; required when not running in a TTY |
| `--global` | `-g` | Install into each agent's global skills directory (e.g. `~/.claude/skills`) instead of the current project |

See the [Coding Agents guide](/docs/guides/coding-agents) for details.

## Rules subcommands

List every built-in rule, its category, default severity, and description:

```bash
npx @docker-doctor/cli@latest rules list
```

Explain a single rule and its fix in detail (the full key or the short name after `docker-doctor/` both work):

```bash
npx @docker-doctor/cli@latest rules explain docker-doctor/no-root-user
```

## Interactive mode

When run in a TTY without `--score` or `--json`, docker-doctor shows a spinner while scanning and, after printing results, offers to scaffold a `.github/workflows/docker-doctor.yml` CI workflow for you. It writes the workflow at the root of the repository that contains the scanned directory. When you scan a subdirectory, the workflow passes that path as the action's `directory` input.

If the scan found issues, it then offers to hand them to a coding agent detected on your machine — launching the agent with the issues as its prompt — or to copy that prompt to your clipboard. See the [Coding Agents guide](/docs/guides/coding-agents).
